# 실행 검증 기록

검증일: 2026-11-03, 실행 환경: Linux / Node.js 24 / Chromium / 소프트웨어 WebGL (SwiftShader).

## 완료한 검사

- `npm install`: 필요한 런타임·개발 패키지 설치 완료, `package-lock.json` 생성
- `npm run typecheck`: 통과
- `npm test`: 스폰·충돌·장애물 관통 방지·근접 상호작용·대상 접근성 검사 5개 통과
- `npm run build`: 정적 페이지 생성과 프로덕션 번들 생성 통과
- `npm run dev`: 포트 3000에서 실행, 첫 화면 HTTP 200
- `npm start -- --port 3001`: 프로덕션 서버 HTTP 200, 실제 방향키 입력으로 캐릭터 좌표 변화 확인, 페이지 오류 없음
- 데스크톱 1440×1000, 모바일 412×839에서 WebGL 렌더링·UI 배치 확인. 모바일 가로 넘침 없음

## 실제 브라우저 조작 검사

프로덕션 서버(`http://127.0.0.1:3001`)를 대상으로 Chromium에서 실제 키보드·포인터·터치 이벤트를 사용했습니다. 순간 이동이나 테스트 전용 이동 명령을 사용하지 않았습니다.

- 데스크톱 이동·카메라·충돌: 방향키/WASD 이동, 입력 해제 후 정지, 드래그 시점 회전, 분수 충돌 확인
- 데스크톱 전체 순회: 벤치 앉기/일어나기와 앉은 동안 이동 차단, 게시판 열기/작성/localStorage 저장/닫기, 대화상자 이동 차단, 카페 입장/광장 복귀, 정원 입장/광장 복귀 통과
- 모바일: 실제 터치 이벤트로 조이스틱 이동/해제 후 정지, 터치 드래그 시점 회전, 세로 화면 가로 넘침 없음 통과

프로젝트에 맞지 않는 중복 시나리오는 Playwright의 `test.skip`으로 제외합니다(데스크톱 2개, 모바일 1개 시나리오). 자동 조작은 카메라 기준 입력을 사용하며 좁은 통로 대신 통행 가능한 경유점을 따라 걷습니다.

재현 명령:

```bash
npm run build
npm start -- --port 3001
# 다른 터미널
PLAYWRIGHT_BASE_URL=http://127.0.0.1:3001 npm run test:e2e
```

## 검증 제한

- 실제 iOS Safari·Android 기기, 저사양 기기의 프레임률·발열·장시간 플레이는 미검증입니다.
- Chromium 모바일 에뮬레이션은 실제 휴대폰의 GPU·터치·노치 동작을 완전히 대신하지 않습니다.
- 실시간 멀티플레이와 서버 기능은 이번 버전에 없으므로 검증 대상이 아닙니다.
- 참고 사이트 `online-camp-kimyunjung.vercel.app`은 환경 네트워크 정책에서 CONNECT 403으로 차단되어 직접 조작하지 못했습니다. 해당 사이트의 그래픽·에셋·소스를 사용하지 않았습니다.

## 개발 중 수정한 문제

- 개발 서버와 프로덕션 빌드가 같은 출력 디렉터리를 사용해 생기는 매니페스트 충돌: 개발 출력은 `.next-dev`, 프로덕션 출력은 `.next`로 분리했습니다.
- 상호작용 버튼 클릭 후 키보드 포커스가 남아 E 키가 막히던 처리: 입력 필드와 대화상자에서만 E 단축키를 차단하도록 수정했습니다.
- 모자와 머리카락 메시가 겹치던 표시를 수정했습니다.
- 광장·정원 꽃과 바닥 타일을 인스턴싱하고 불필요한 렌더 호출을 줄였습니다. 정적인 마을 그림자는 공간 진입 시 계산하며 캐릭터는 이동하는 접지 그림자를 사용합니다.
- 저프레임 환경에서 이동량이 과도하게 줄어들지 않도록 이동 delta와 시각 보간 delta를 분리했습니다. 충돌은 작은 구간으로 나눠 계속 판정합니다.
- 장시간 파일 변경 후 개발 서버 응답이 지연되는 현상을 확인해 서버를 재시작했고, 최종 기능 검사는 프로덕션 서버에서 수행했습니다.
- 초기 자동 검사에서 렌더 완료 전 고정 시간만 기다리거나 분수를 가로지르려던 경로를 사용한 실패가 있었습니다. 실제 프레임 상태를 기다리고 통행 가능한 경유점을 따라가도록 테스트를 수정했습니다.
